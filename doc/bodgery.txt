SETUP                                                      *bodgery-setup*
                                                        *bodgery.setup()*

>lua
  require('bodgery').setup({})
<
Loading the plugin defines the session restore autocommands, and a config
with its command for each harness installed with a config directory
(`claude` on the path and `$CLAUDE_CONFIG_DIR` or `~/.claude`).

`setup()` stores a config and defines its command. It loads no other module.
Each call creates or replaces the config named `name`, so several configs,
for the same harness or different ones, run side by side, and removes the
config loading created for its harness.

                                                      *bodgery-config-arg*
Functions taking {config} accept a config name, or a table overriding the
config its `name` field names:
>lua
  require('bodgery').toggle(nil, { name = 'claude', active = { 'global', 'new' } })
<

The first terminal opened starts a
localhost server that carries Claude's hooks, the `nvim` MCP server, and the
IDE websocket, and writes the lockfile Claude's `/ide` command reads
(`$CLAUDE_CONFIG_DIR/ide/<port>.lock`, or `~/.claude/ide/`). Options are
validated when first read, so a bad option raises then.

Terminals get the harness name as their filetype (`claude`), and drafts opened
from the prompt editor get `bodge-prompt`.

Only terminals opened by the plugin (|:Claude|, |bodgery.open()|) get
hooks, events, and custom tools. Each terminal authenticates with its own
token, passed in the `BODGERY_TOKEN` environment variable.

OPTIONS                                                  *bodgery-options*

Defaults:
>lua
  {
    name = <harness>,
    harness = 'claude',
    command = <harness, capitalized>,
    cmd = { 'claude' },
    hooks = {},
    tools = {},
    execute_code = false,
    selection = { auto = true },
    on_busy = 'error',
    active = { 'window', 'tab', 'global', 'new' },
    root_markers = { '.git' },
    show = { window = <split of the current window> },
    restore = { max_age = 30 * 24 * 60 * 60 },
    editor = { open = function(file) vim.cmd.split(file) end },
    diff = { inline = true, window = <nearest window to Claude> },
    ccd_dir = '~/Library/Application Support/Claude/claude-code-sessions',
  }
<
name ~
    Key of this config in `require('bodgery').configs`.

harness ~
    The agent this config launches. Only `'claude'` exists.

command ~
    User command that opens this config, `Claude` for the `claude` harness.
    Configs sharing a command are told apart by name: `:Claude work` opens
    the config named `work`, and `:Claude` alone opens the first config set
    up with that command. A command no config uses any more is deleted.

cmd ~
    Command and default flags. `args` from |bodgery.open()| and |:Claude|
    are appended.

hooks ~
    Map from hook event to `function(input)`. `input` is Claude's hook
    payload. A returned table is sent back to Claude as the hook response,
    so a callback can deny a tool or add context. Events: `SessionStart`,
    `PreToolUse`, `PostToolUse`, `SubagentStart`, `SubagentStop`,
    `UserPromptSubmit`, `Stop`, `Notification`, `SessionEnd`. Errors are
    reported with |vim.notify()| and Claude receives `{}`.

tools ~
    Custom MCP tools, see |bodgery-tools|.

execute_code ~
    Serve the `executeCode` IDE tool, which runs Lua from Claude in this
    Neovim. Never put it on a permission allowlist: one approval covers
    |vim.fn.system()|.

selection.auto ~
    Send the selection or cursor position to Claude on |WinLeave| from file
    windows and when leaving Visual mode. Claude attaches the latest one to
    the next prompt.

on_busy ~
    What typing into a terminal does while the agent is working or waiting
    on a permission prompt, as |bodgery.resume()| does: `'error'` raises,
    `'interrupt'` sends <Esc> first, `'queue'` waits for the next idle
    status, and `'prompt'` asks through |vim.ui.select()|.

active ~
    Resolvers tried in order to find the terminal a call acts on. See
    |bodgery-active|.

root_markers ~
    Markers |vim.fs.root()| looks for in the `project` resolver.

show.window ~
    `function(ctx, term?): integer` returning the window that shows a hidden
    terminal, or a new one when `term` is nil. `ctx` has the current `win`,
    `buf`, and `tab`. The default splits the current window, vertically when
    it is wide.

restore.max_age ~
    Seconds before an unused entry leaves the restore state file.

editor.open ~
    `function(file)` that shows the <C-g> draft. See |bodgery-editor|.

diff.window ~
    `function(): integer` returning the window for a proposed edit. IDE
    requests can't tell which terminal sent them, so `diff`, `execute_code`,
    and `selection` come from the last used Claude terminal's config.

diff.inline ~
    Mark inserted and removed characters within changed lines.

ccd_dir ~
    Root of the Claude desktop app's session index, read for titles and
    archive state.

==============================================================================
COMMANDS                                                *bodgery-commands*

                                                                     *:Claude*
:[mods] Claude [config] [args]
    Start Claude in a split, with `args` appended to `cmd`. A first argument
    naming a config that shares the command picks that config. The command
    name comes from `command`. Modifiers work as they do for |:split|:
    `:vertical Claude`, `:tab Claude`, `:botright Claude`.

==============================================================================
FUNCTIONS                                                    *bodgery-api*

                                                         *bodgery.open()*
open({config} [, {opts}])
    Start {config}'s agent in a terminal and return its buffer. Without
    `mods` or `win` the terminal takes the current window, as |:terminal|
    does. Fields of {opts}:
      `cwd`     working directory
      `args`    list appended to `cmd`
      `mods`    |nvim_parse_cmd()| modifiers; open in a split built from them
      `win`     window to start in, replacing its buffer

                                                       *bodgery.toggle()*
toggle([{bufnr} [, {config}]])
    Hide the target terminal (|bodgery-active|) when it shows in the current
    tab: close its window, or show the alternate buffer in it when it is the
    tab's only window. Otherwise show it in the window from `show.window`
    and enter it. When the chain reaches `new`, start {config}'s agent there.

                                                         *bodgery.tool()*
tool({name}, {spec})
    Register or replace a custom tool. See |bodgery-tools|.

                                               *bodgery.send_selection()*
send_selection([{bufnr} [, {config}]])
    Send the current Visual selection to the target terminal, or the last
    one in this buffer.

                                              *bodgery.send_at_mention()*
send_at_mention([{range} [, {bufnr} [, {config}]]])
    Mention the current file in the target terminal's prompt. {range} is an
    optional `{ first, last }` pair of 1-based lines.

                                                       *bodgery.resume()*
resume({id} [, {bufnr} [, {config}]])
    Resume session {id} in the target terminal by typing `/resume {id}`,
    subject to `on_busy`. When the chain reaches `new`, start {config}'s
    agent in the current window with `--resume {id}`.

                                                     *bodgery.sessions()*
sessions({config} [, {filter}])
    Iterator over the sessions of {config}'s harness, newest first. Each record has `id`,
    `last_activity` (seconds since the epoch), `cwd`, `title`, `archived`,
    `live` (`{ pid, status, name }` for a running Claude), and `bufnr` when a
    plugin terminal holds it. Fields of {filter}:
      `cwd`       only sessions started in this directory
      `archived`  only archived, or only unarchived, sessions
      `fields`    fields to fill beyond `id` and `last_activity`
    Leaving the loop early skips reading the remaining transcripts.

                                                      *bodgery.touched()*
touched({session_id}, {config})
    Files the agent read or edited in the session.

                                                     *bodgery.subtasks()*
subtasks({session_id}, {config})
    Subagents and background commands of the session. Each has `id`, `kind`
    (`'agent'` or `'bash'`), `description`, `open`, and `path` (the agent's
    transcript, or a finished command's output).

                                                         *bodgery.stop()*
stop()
    Stop the server and remove the lockfile. The next terminal opened starts
    them again.

                                                          *bodgery-active*
Functions acting on "the target terminal" use {bufnr} when given, then the
terminal in the current window, then the first match of {config}'s `active`
list (the default list without {config}). Entries are functions
`fn(ctx, config): bufnr?` or these names:
  `window`   the terminal last opened or entered from the current window
  `buffer`   the same for the current buffer
  `tab`      the same for the current tab
  `global`   the terminal last opened or entered
  `project`  the last used terminal whose working directory has the same
             root as the current buffer (`root_markers`)
  `pick`     ask through |vim.ui.select()|, skipped with no terminals
  `new`      start a terminal from {config}
  `error`    raise
The records behind the first four are `w:`, `b:`, `t:`, and `g:bodgery_term`.

PICKERS                                                  *bodgery-pickers*

`require('bodgery.select')` offers three pickers through
|vim.ui.select()|. Each takes an optional `on_choice(item)` that replaces the
default action.

sessions({config} [, {opts}])
    Unarchived sessions started in `opts.cwd` (default: |getcwd()|). Choosing
    one shows the terminal holding it, or resumes it with
    |bodgery.resume()|.

subtasks([{opts} [, {config}]])
    Subtasks of `opts.session_id` (default: the target terminal's session).
    {config} is required with `opts.session_id`. Choosing one opens its
    transcript or output.

touched([{opts} [, {config}]])
    Files touched in `opts.session_id`, as for `subtasks`. Choosing one
    edits it.

EVENTS                                                    *bodgery-events*

|User| autocommands. Every `ev.data` carries `session_id`, `bufnr`, and
`config`, the config name.

ClaudeSessionEnter      a terminal starts or switches to a session; `source`
                        is Claude's SessionStart source when known
ClaudeSessionLeave      a terminal's session ends or is replaced. On
                        `/resume` and `/clear` it fires before the new
                        session's ClaudeSessionEnter.
ClaudeToolUsePre        before a tool runs: `tool_name`, `tool_input`,
                        `tool_use_id`
ClaudeToolUsePost       after a tool runs, adding `tool_response`
ClaudeFilesChanged      the touched list grew: `files`
ClaudeStatusChanged     `status` became `'busy'`, `'idle'`, or `'waiting'`
ClaudeSubtaskOpen       a subagent or background command started: `subtask`
ClaudeSubtaskClose      it finished: `subtask`

>lua
  vim.api.nvim_create_autocmd('User', {
    pattern = 'ClaudeStatusChanged',
    callback = function(ev)
      if ev.data.status == 'waiting' then
        vim.notify('Claude needs input in buffer ' .. ev.data.bufnr)
      end
    end,
  })
<

TOOLS                                                      *bodgery-tools*

Tools from `opts.tools` and |bodgery.tool()| are served by the `nvim` MCP
server, and Claude sees them as `mcp__nvim__<name>`. Tools registered during
a session show up in Claude's next tool listing.
>lua
  require('bodgery').tool('buffer_names', {
    description = 'List the files open in Neovim',
    input_schema = { type = 'object', properties = {} },
    handler = function(args, ctx)
      return vim.tbl_map(vim.api.nvim_buf_get_name, vim.api.nvim_list_bufs())
    end,
  })
<
`handler(args, ctx)` runs in this Neovim. `ctx` has `session_id` and the
calling terminal's `bufnr`. A returned string is sent as text and a table as
JSON. An error becomes an error result for Claude.

Built in:
  `nvim_help`         the help section from a tag to the next tag
  `nvim_help_search`  help tags matching a pattern
  `nvim_helpgrep`     help text matching a pattern, leaving the quickfix
                      list alone
  `nvim_screen`       the screen as text, one line per row; with
                      `highlights`, also `{ row, first, last, group }` runs
                      in 1-based screen cells. Every UI redraws fully once
                      per call.

Claude also calls `getDiagnostics` before and after each edit. The reply
covers |vim.diagnostic| entries and treesitter syntax errors in loaded
buffers, so Claude sees syntax errors its edit introduced.

==============================================================================
DIFF REVIEW                                                 *bodgery-diff*

When Claude proposes an edit through the IDE connection (`/ide`), the
proposed contents open in a buffer in the window chosen by `diff.window`.
Added lines are highlighted and removed lines show as virtual lines. The
buffer is editable.

  |:w|                     accept, and Claude writes the buffer's contents,
                         including your edits
  delete or hide buffer  reject

Answering in the terminal instead closes the review. Afterwards the window
gets its previous buffer back, or closes if it was opened for the review.

==============================================================================
PROMPT EDITOR                                             *bodgery-editor*

<C-g> in Claude opens the draft prompt with `editor.open`, by default in a
|:split|. Hiding or deleting the buffer sends the text back to Claude.

==============================================================================
SESSION RESTORE                                          *bodgery-restore*

|:mksession| saves Claude terminals, and sourcing the session file relaunches
each one with `--resume`, continuing its conversation. Source the session
file after the plugin loads and the terminal's config exists, or Neovim reruns the saved command and
starts a new conversation. When the conversation is already open elsewhere,
the terminal starts a new one and says so.

The map from terminal to session lives in
`stdpath('state')/bodgery/terminals.json`.
